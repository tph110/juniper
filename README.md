# 🌿 Juniper

Gamified AI patient consultation simulator for healthcare professionals and students.

The student consults with an AI patient — an animated, talking portrait — takes a
history in free text, and is prompted at key moments to commit to clinical
decisions that branch the rest of the consultation. Every run ends with a scored
debrief against authored, guideline-based feedback.

## Architecture

Static frontend + serverless API routes (same pattern as Ambient — deploys to
Vercel with no build step).

| Layer | Tech | Cost |
|---|---|---|
| Patient dialogue | Kimi K2.6 via OpenRouter (Western hosting) | ~free per consult |
| Patient voice | MiniMax `speech-02-turbo` (international endpoint) | ~1–3p per consult |
| Patient avatar | Code-drawn SVG portrait, audio-reactive mouth via Web Audio | free |
| Scenario engine | Authored JSON-like case files in `scenarios/` | — |

The scenario file is the single source of truth: the browser reads it for the
UI, decision points and debrief; `/api/chat.js` reads it to build the patient's
system prompt. Authored decision options, examination findings and feedback are
never generated by the LLM — the model only role-plays the patient inside the
authored case sheet.

## Run locally

```
node dev-server.js
```

Open http://localhost:4620. With no API keys configured the app runs in **demo
mode**: canned patient replies and the browser's built-in voice — the full flow
works end to end.

For real AI dialogue and voice, copy `.env.example` to `.env`, fill in the keys,
and run with:

```
node --env-file=.env dev-server.js
```

## Deploy

Push to a Git repo and import into Vercel (framework: none, no build step).
Set `OPENROUTER_API_KEY`, `MINIMAX_API_KEY` and `MINIMAX_GROUP_ID` in the
project's Environment Variables.

## Adding scenarios

Copy `scenarios/margaret-hughes.js` and edit: the `caseSheet` (patient persona +
hidden information and reveal rules), `stages` (each with an optional decision
point: options carry `quality`, `feedback`, an authored `patientReaction` and
the `next` stage), `examination` findings, and `learningPoints`. Clinical
review of every scenario before release is the quality gate that matters.
